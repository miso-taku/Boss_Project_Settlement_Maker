# F5: エラーハンドリング・ローディング表示 — 要求

## 背景 / 目的

- **背景**: F4 で生成実行・返信案表示・コピー機能が実装され、基本的なローディング状態とエラー状態の管理が実装された。しかし、エラーハンドリングは基本的な実装のみで、HTTPステータスコード別の処理やユーザーフレンドリーなエラーメッセージの表示が不足している。また、ローディング表示も「生成中...」というテキストのみで、視覚的なフィードバックが不十分である。
- **目的**: `ReplyForm` コンポーネントと API クライアントに詳細なエラーハンドリングを実装し、HTTPステータスコード別（400, 404, 500等）やネットワークエラー、バリデーションエラーなどに応じた適切なエラーメッセージを表示する。また、ローディング表示を改善し、スピナーやプログレスバーなどの視覚的なフィードバックを提供する。

## スコープ（やること / やらないこと）

### やること

- エラーハンドリングの改善
  - HTTPステータスコード別のエラーメッセージ（400: バリデーションエラー、404: リソース未找到、500: サーバーエラー等）
  - ネットワークエラー（接続エラー、タイムアウト等）の適切な処理
  - バリデーションエラー（API からの詳細エラーメッセージ）の表示
  - ユーザーフレンドリーなエラーメッセージの表示（技術的なエラーメッセージをユーザー向けに変換）
  - エラー表示のUI改善（エラーメッセージの見やすさ、アクセシビリティ）
- ローディング表示の改善
  - スピナーまたはプログレスバーの実装
  - ローディング中の視覚的フィードバックの改善
  - ローディング状態の明確な表示（ボタンの disabled 状態に加えて、視覚的なインジケーター）
- API クライアントのエラーハンドリング改善
  - HTTPステータスコード別のエラー処理
  - ネットワークエラーの適切な処理
  - エラーレスポンスの詳細情報の取得と伝達
- `./docs/implementation-tasklist.md` の F5 を完了に更新

### やらないこと

- リトライ機能（必要になったら別タスクで検討）
- エラー通知の永続化（トーストライブラリの導入は検討するが、今回は基本的な実装のみ）
- オフライン状態の検出（必要になったら別タスクで検討）
- エラーログの外部サービスへの送信（必要になったら別タスクで検討）

## 受け入れ条件（Given-When-Then）

- **Given** 生成実行機能が実装済み（F4 完了）
- **Given** 基本的なエラーハンドリングが実装済み（F4 完了）
- **When** API 呼び出し中にエラーが発生する
- **Then** HTTPステータスコードに応じた適切なエラーメッセージが表示される
- **And** ネットワークエラー時にユーザーフレンドリーなメッセージが表示される
- **And** バリデーションエラー時に詳細なエラーメッセージが表示される
- **When** API 呼び出し中（ローディング状態）
- **Then** スピナーまたはプログレスバーなどの視覚的なインジケーターが表示される
- **And** ローディング状態が明確に示される
- **And** `./docs/implementation-tasklist.md` の F5 が完了に更新されている

## 未決事項 / リスク / 仮定

- **仮定**: スピナーまたはプログレスバーは、CSS のみで実装するか、軽量なライブラリを使用する。重いライブラリの導入は避ける。
- **仮定**: エラーメッセージの表示は、既存のエラー表示UI（F4 で実装済み）を改善する形で実装する。トーストライブラリの導入は検討するが、今回は基本的な実装のみとする。
- **仮定**: HTTPステータスコード別のエラーメッセージは、一般的なメッセージを表示する。詳細なエラーメッセージは API レスポンスから取得できる場合はそれを優先する。
- **仮定**: ネットワークエラーの検出は、`fetch` API のエラーやタイムアウトを検出する。タイムアウトの設定は必要に応じて実装する。
- **リスク**: エラーメッセージの多言語対応は今回は考慮しない（日本語のみ）。
- **リスク**: アクセシビリティ（ARIA 属性等）の実装は必要最小限とする。
