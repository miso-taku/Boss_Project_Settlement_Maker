# 仕様変更: 返信案を 1 案に絞る — 要求

## 背景 / 目的

- 現状、バックエンドは返信案を複数（2〜3案）生成する仕様になっている。
- 実際の動作では似たような回答が多く、複数案のメリットが薄い。
- **返信案を 1 案に絞る**ことで、品質に集中し、UX をシンプルにする。

## スコープ

### やること

- **仕様**: 返信案の生成数を「複数（2案以上）」から「1案」に変更する。
- **永続ドキュメント**: product-requirements.md / functional-design.md / architecture.md / glossary.md を修正し、「1案」に統一する。
- **バックエンド**: AI プロンプトを「1件生成」に変更する。API 契約は `drafts` をリストのまま維持し、要素数が 1 であることを期待する。
- **テスト**: 統合テスト・アプリケーション単体テストで「1案返る」ことを期待するように修正する。
- **implementation-tasklist.md**: 本仕様変更を反映（新規タスクまたは注記）する。

### やらないこと

- API の破壊的変更（`drafts` はリストのまま。フロントは「1要素のリスト」として扱える）。
- フロントエンドの実装（未着手のため、ドキュメントと契約が正しければ後で 1 案表示に合わせる）。
- 認証・履歴・その他機能の追加。

## 受け入れ条件

- **Given** 依頼文＋自分の状況を POST する  
  **When** 返信案生成 API を呼ぶ  
  **Then** 200 で `drafts` が **1 件**のリストとして返る。

- **Given** 永続ドキュメントを開く  
  **When** 返信案の数に関する記述を確認する  
  **Then** 「1案」「1件」に統一されている（「2案以上」「2〜3案」「複数パターン」等の記述が残っていない）。

- **Given** バックエンドの AI プロンプトを確認する  
  **When** 生成・作り直しの指示を読む  
  **Then** 「1件」生成する旨が明記されている。

- 既存の pytest（unit + integration）がすべて通過する。

## 影響範囲

| 領域 | 内容 |
|------|------|
| BE | プロンプト（pydantic_ai_adapters.py）、統合テスト・アプリ単体テストの期待値 |
| API | 契約は変更しない（drafts は list のまま）。期待される要素数が 1 になる。 |
| FE | 未実装のためコード変更なし。将来実装時は 1 案表示に従う。 |
| Docs | product-requirements, functional-design, architecture, glossary, implementation-tasklist |

## 受け入れ条件チェック結果（モード3）

- 返信案生成 API が 200 で drafts 1 件を返す: プロンプトを1件に変更し、統合テストで len(data["drafts"]) == 1 を検証。達成。
- 永続ドキュメントが「1案」に統一されている: product-requirements, functional-design, architecture, glossary を修正済み。達成。
- AI プロンプトが「1件」生成を指示: PydanticAIGenerateAdapter / PydanticAIReviseAdapter のプロンプトを修正済み。達成。
- 既存 pytest がすべて通過: uv run pytest -q で 23 テスト通過。達成。

## 未決事項 / リスク / 仮定

- 仮定: 「1案」で十分とする。将来的に再度「複数案」が必要になった場合は別タスクで仕様を戻すか検討する。
- リスク: 既存の統合テストが「2件返る」モックに依存しているため、モックとアサーションを 1 件に合わせる必要がある。
