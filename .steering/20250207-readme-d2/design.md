# D2: README.md 作成 — 設計

## 方針

- README は「入口」に徹する。詳細は ./docs と AGENTS.md に委譲する。
- 起動方法は architecture.md・repository-structure.md の想定に合わせて記載する（backend: uv, frontend: npm 等）。ディレクトリ未作成の場合は「実装後に利用可能」と明記する。

## データフロー

- なし（ドキュメント追加のみ）。

## 構成案（README.md のセクション）

1. **プロジェクト名・サブタイトル** — product-requirements.md から転記。
2. **概要** — 1〜2文で何ができるか。
3. **技術スタック** — architecture.md の表を簡略化して記載。
4. **前提条件** — Python 3.x, Node.js, OpenAI API キー（環境変数）。
5. **起動方法** — backend / frontend の手順（uv sync, uv run, npm run dev 等）。未実装部分は「予定」と明記。
6. **ドキュメント** — ./docs 一覧へのリンク、AGENTS.md への言及。
7. **ライセンス・貢献** — 必要ならプレースホルダで記載（本タスクでは最小限で可）。

## テスト戦略

- 本タスクはドキュメント追加のため、自動テストは不要。受け入れ条件は目視確認で充足。

## ドキュメント更新方針

- README.md を新規作成。
- ./docs の既存ファイルは変更しない。
- 作業完了時に `./docs/implementation-tasklist.md` の D2 を「完了」に更新する。

## 全体タスク反映方針

- `./docs/implementation-tasklist.md` の D2 を「完了」にし、完了日を記録する。実装サマリーの「完了」数を 1 増やし、「未着手」を 1 減らす。

---

## 結果と学び（モード3）

- **採用案の妥当性**: 構成案（プロジェクト名・概要・技術スタック・前提条件・起動方法・ドキュメント・ライセンス）のまま README.md を作成。起動方法は「現時点では未実装」と明記し、architecture.md の想定コマンドを記載した。
- **想定外**: 特になし。
- **改善点**: 実装完了（B1/B2, F1 等）後に、起動方法のモジュールパス・ポート等を実際の構成に合わせて更新する。
