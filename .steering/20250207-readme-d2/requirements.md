# D2: README.md 作成 — 要求

## 背景 / 目的

- **背景**: 実装タスクリスト D1 で永続ドキュメント（./docs）が整備済み。リポジトリの入口として、プロジェクト概要と起動方法を記載した README.md が未作成。
- **目的**: 新規クローン・参加者が「何のプロジェクトか」「どう動かすか」をすぐ把握できる README.md を作成する。

## スコープ（やること / やらないこと）

### やること

- プロジェクト概要（プロダクト名・サブタイトル・一言説明）
- 技術スタック（FE: React, BE: FastAPI + PydanticAI）の記載
- 起動方法（バックエンド・フロントエンドの想定コマンド。実装前は「予定」として記載）
- ドキュメント・ルールへのリンク（./docs, AGENTS.md）
- 必要に応じて前提条件（Python/Node 等）・環境変数（OpenAI API キー等）の記載

### やらないこと

- 実装タスク D2 以外のコード・設定変更
- ./docs の既存内容の変更（README は docs を参照する側のみ）

## 受け入れ条件（Given-When-Then）

- **Given** リポジトリをクローンした人が README.md を開く  
- **When** 冒頭から起動方法まで読む  
- **Then** プロダクトの目的と技術構成が分かり、BE/FE の起動コマンド（または「実装後に追記」の旨）が分かる  
- **And** ./docs や AGENTS.md へのリンクがあり、詳細に誘導できる  

## 影響範囲

| 領域 | 内容 |
|------|------|
| FE | なし |
| BE | なし |
| API | なし |
| DB | なし |
| Docs | README.md を新規作成。他は参照のみで変更なし |

## 未決事項 / リスク / 仮定

- **仮定**: backend/ frontend/ は未実装のため、起動方法は「予定」または「実装後に追記」とし、architecture.md 等に記載のコマンド（uv, npm）を記載する形でよい。
- 未決事項なし。
