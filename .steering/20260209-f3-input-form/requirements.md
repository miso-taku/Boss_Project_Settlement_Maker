# F3: 入力フォーム（依頼文・残り時間・優先度・制約）— 要求

## 背景 / 目的

- **背景**: F2 で API クライアントが実装され、フロントエンドからバックエンドの返信案生成 API を呼び出す準備が整った。次に、ユーザーが依頼文と自分の状況を入力するためのフォーム UI を実装する必要がある。
- **目的**: `frontend/src/app/page.tsx` または `frontend/src/components/` 配下に、依頼文・残り時間・優先度・制約を入力するフォームコンポーネントを実装する。functional-design.md 2.1 に従い、入力エリアを構成する。

## スコープ（やること / やらないこと）

### やること

- 入力フォームコンポーネントの実装
  - 依頼文：テキストエリア（自由文・必須）
  - 残り時間：数値入力（単位は時間・任意・0以上）
  - 優先度：3段階のラジオまたはセレクト（"high" | "medium" | "low"・任意）
  - 制約：テキストエリア（自由文・任意）
- フォームの状態管理（React state）
- 基本的な入力バリデーション（UI 都合のみ。最終的な整合性は BE で担保）
- `page.tsx` にフォームを統合
- `./docs/implementation-tasklist.md` の F3 を完了に更新

### やらないこと

- 生成実行ボタンと API 呼び出し（F4 で実施）
- 返信案表示・コピー機能（F4 で実施）
- エラーハンドリングの UI 表示（F5 で実施）
- ローディング表示（F5 で実施）
- React Hook Form 等のフォーム管理ライブラリの導入（今回は標準の React state を使用。必要に応じて F4 以降で検討）

## 受け入れ条件（Given-When-Then）

- **Given** API クライアントが実装済み（F2 完了）
- **Given** Next.js プロジェクトが初期化済み（F1 完了）
- **When** フォームを表示する
- **Then** 依頼文・残り時間・優先度・制約の入力フィールドが表示される
- **And** 依頼文はテキストエリアで入力できる
- **And** 残り時間は数値で入力できる（単位は時間）
- **And** 優先度は3段階（高・中・低）で選択できる
- **And** 制約はテキストエリアで入力できる
- **And** 入力値が正しく状態管理される
- **And** `./docs/implementation-tasklist.md` の F3 が完了に更新されている

## 未決事項 / リスク / 仮定

- **仮定**: フォーム管理は標準の React state（`useState`）を使用する。React Hook Form は必要に応じて F4 以降で導入を検討する。
- **仮定**: バリデーションは UI 都合のみ（例：依頼文が空の場合の警告表示）。最終的な整合性はバックエンドの API で担保する。
- **仮定**: 優先度のラベルは「高・中・低」とする（値は "high" | "medium" | "low"）。
- **仮定**: 残り時間の単位は「時間」とする（例：1.5 時間）。入力フィールドには単位表示を追加する。
- **リスク**: フォームの状態管理が複雑になる可能性がある。必要に応じて F4 以降で React Hook Form に移行する。
- **リスク**: バリデーションエラーの表示方法が一貫しない可能性がある。F5 でエラーハンドリングを実装する際に統一する。
