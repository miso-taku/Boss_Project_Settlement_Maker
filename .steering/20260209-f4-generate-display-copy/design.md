# F4: 生成実行・返信案表示（1件）・コピー — 設計

## 方針

- **DDD 境界**: フロントエンドは UI 都合（表示制御・入力補助・UX）に集中する。業務ルール（返信案の生成ロジック・バリデーション）はバックエンド（Domain）に寄せる。
- **責務分割**: `ReplyForm` コンポーネントに生成実行ボタン・API呼び出し・返信案表示・コピー機能を統合する。必要に応じて返信案表示コンポーネントを分離する。
- **状態管理**: React state（`useState`）でローディング状態・エラー状態・返信案データを管理する。サーバー状態の管理は F5 以降で React Query 等の導入を検討する。

## データフロー

```
[ユーザー]
  → フォームに入力（依頼文・残り時間・優先度・制約）
  → 生成実行ボタンをクリック
[ReplyForm コンポーネント]
  → フォームの入力値を取得
  → API クライアント関数（generateReplyDrafts）を呼び出し
  → ローディング状態を true に設定
  → API レスポンスを受け取る
  → 返信案データを状態に保存
  → ローディング状態を false に設定
  → 返信案を表示
  → ユーザーが「コピー」ボタンをクリック
  → navigator.clipboard.writeText() でコピー
  → コピー成功時のフィードバックを表示
```

## API変更

- 今回は API 変更なし。既存の `POST /api/v1/reply-drafts` エンドポイントを利用する。
- **リクエスト**: `GenerateReplyDraftsRequest`
  - `request_text`: string（必須・非空）
  - `remaining_hours`: number | null（任意・0以上）
  - `priority`: "high" | "medium" | "low" | null（任意）
  - `constraints`: string（任意・空文字可）
- **レスポンス**: `GenerateReplyDraftsResponse`
  - `drafts`: `ReplyDraftItem[]`（要素数は1件）
    - `text`: string（返信案の本文）

## 代替案と採用理由

- **コンポーネント構成: 統合 vs 分離**: `ReplyForm` コンポーネントに生成実行・返信案表示・コピー機能を統合する。F4 では機能が比較的シンプルなため、統合で問題ない。必要に応じて F5 以降で分離を検討する。**統合を採用**。
- **状態管理: React state vs React Query**: 今回は標準の React state（`useState`）を使用する。F5 でエラーハンドリング・ローディング表示を詳細に実装する際に、React Query の導入を検討する。**React state を採用**。
- **コピー機能: navigator.clipboard vs ライブラリ**: `navigator.clipboard.writeText()` を使用する。モダンブラウザでサポートされており、追加のライブラリが不要。**navigator.clipboard を採用**。
- **コピー成功フィードバック: ボタン表示変更 vs トースト**: ボタンの表示変更（例：「コピー済み」）または簡易的なトースト表示とする。詳細なトーストライブラリの導入は F5 以降で検討する。**ボタン表示変更を採用**。
- **返信案表示: プレーンテキスト vs マークダウン**: 返信案のテキストをそのまま表示する（改行は保持）。マークダウンのレンダリングは必要に応じて F5 以降で検討する。**プレーンテキストを採用**。

## 結果と学び（モード3）

- **採用案の妥当性**: `ReplyForm` コンポーネントに生成実行・返信案表示・コピー機能を統合した実装は、F4 では機能が比較的シンプルなため、統合で問題なく適切だった。標準の React state（`useState`）を使用した状態管理は、ローディング状態・エラー状態・返信案データの管理に適していた。`navigator.clipboard.writeText()` を使用したコピー機能は、モダンブラウザでサポートされており、追加のライブラリが不要で適切だった。コピー成功時のフィードバックとしてボタンの表示変更を採用したが、視認性が高く適切だった。

- **想定外**: `npm run lint` の実行環境に問題があり、lint の実行ができなかったが、TypeScript の型チェックで問題がないことを確認できた。テスト実行は F6 でテスト設定を追加予定のため、今回はテストファイル作成のみで完了とした。コピー機能のフォールバック（`document.execCommand("copy")`）を実装したが、モダンブラウザでは `navigator.clipboard.writeText()` がサポートされているため、フォールバックが実際に使用されることは少ないと想定される。

- **改善点**: 次回（F5）でエラーハンドリング・ローディング表示を詳細に実装する際に、エラーメッセージの表示方法を統一する必要がある。また、ローディング表示については、現在はボタンの disabled 状態とテキスト変更のみだが、F5 でスピナーやプログレスバーなどの詳細な UI を実装する必要がある。スタイリングについては、現在はインラインスタイルで実装しているが、必要に応じて CSS Modules や Tailwind CSS の導入を検討する。API 呼び出し中の重複実行を防ぐために、ボタンの disabled 状態で制御しているが、F5 でより詳細な制御を実装する必要がある。
