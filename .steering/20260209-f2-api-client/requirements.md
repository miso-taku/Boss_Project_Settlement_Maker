# F2: API クライアント（返信案生成 API 呼び出し）— 要求

## 背景 / 目的

- **背景**: F1 で Next.js プロジェクトが初期化され、基本的なプロジェクト構造が整った。次に、フロントエンドからバックエンドの返信案生成 API を呼び出すための API クライアントを実装する必要がある。
- **目的**: `frontend/src/api/` 配下に返信案生成 API を呼び出すクライアント関数を実装する。architecture.md 4.2 に従い、API クライアントは一箇所に集約する。リクエスト/レスポンスの型定義も含める。

## スコープ（やること / やらないこと）

### やること

- `frontend/src/api/` 配下に API クライアント関数を実装
- 返信案生成 API（`POST /api/v1/reply-drafts`）を呼び出す関数を作成
- リクエスト/レスポンスの TypeScript 型定義を実装（バックエンドの DTO と整合）
- エラーハンドリングの基本実装（HTTP ステータスコードの処理）
- API のベース URL を環境変数（`NEXT_PUBLIC_API_BASE_URL`）で設定可能にする
- `./docs/implementation-tasklist.md` の F2 を完了に更新

### やらないこと

- 入力フォーム実装（F3 で実施）
- 返信案表示・コピー機能（F4 で実施）
- エラーハンドリングの UI 表示（F5 で実施）
- ローディング表示（F5 で実施）
- React Query 等の状態管理ライブラリの導入（F3 以降で必要に応じて検討）
- OpenAPI からの型自動生成（今回は手動で型定義、必要に応じて F3 以降で検討）

## 未決事項 / リスク / 仮定

- **仮定**: バックエンドのデフォルトポートは 8000（`http://localhost:8000`）。開発環境では CORS 設定が必要な可能性があるが、FastAPI のデフォルト設定で対応可能と仮定する。
- **仮定**: API クライアントは `fetch` API を使用する（Next.js 標準）。必要に応じて後で axios 等に変更可能。
- **仮定**: 環境変数は `NEXT_PUBLIC_API_BASE_URL` を使用し、デフォルト値は `http://localhost:8000` とする。
- **リスク**: CORS エラーが発生する可能性がある。バックエンドで CORS ミドルウェアが設定されていない場合は、実装時に確認・対応する。
- **リスク**: 型定義がバックエンドの DTO と不一致になる可能性がある。実装時にバックエンドの DTO 定義を確認し、整合性を保つ。
