# requirements.md — バックエンド AI/MCP ログ出力

## 背景 / 目的

- デバッグ・監査・品質改善のため、AI エージェントの入出力と MCP から取得した内容をログファイルに記録する。
- 記録対象: (1) PydanticAI の Generate / Check / Revise のプロンプトと出力、(2) Calendar MCP の list-calendars / list-events の呼び出し引数と取得結果。

## スコープ

### やること

- 上記の「記録対象」をファイルログに書き出す仕組みの追加。バックエンドのみ。
- Infrastructure 層（pydantic_ai_adapters, calendar_mcp_adapter）でのログ出力実装。

### やらないこと

- フロントエンドの変更。
- 既存 API 契約の変更。
- ログの外部送信（例: クラウドログサービス）は今回スコープ外とする。

## 受け入れ条件（Given-When-Then）

- **Given** 返信案生成 API（POST /api/v1/reply-drafts）を呼び出す。カレンダーソースで呼び出す場合も含む。
- **When** 正常に処理が完了する。
- **Then** 設定したログ出力先に、AI のプロンプト・出力および MCP のツール名・引数・取得結果が記録されていること。既存テストはすべてパスすること。

## 影響範囲

| 対象 | 内容 |
|------|------|
| BE ソース | infrastructure（pydantic_ai_adapters, calendar_mcp_adapter）、必要なら interface のログ設定 |
| API/契約 | 変更なし |
| DB | なし |
| Docs | `./docs/implementation-tasklist.md` に本タスクを追加し、完了時に更新。必要なら `./docs/architecture.md` に「ログ出力」の記載を追加。 |

## 未決事項 / リスク / 仮定

- **仮定**: ログには依頼文・返信案・カレンダー予定などが含まれるため、取り扱い（保存場所・権限・保持期間）は運用で決める。
- **リスク**: ログに個人情報・業務内容が含まれるため、ファイルのアクセス制御と保持期間の運用方針を決めておく必要がある。
- **未決**: ログレベル（DEBUG/INFO）、ログファイルのパス・ローテーション仕様は design で案を出し、必要なら requirements に追記する。
