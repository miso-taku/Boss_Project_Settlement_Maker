# 機能設計書（Functional Design）

## 1. 機能一覧

| 機能ID | 機能名 | 概要 | 優先度 |
|--------|--------|------|--------|
| F1 | 依頼文入力 | 相手の依頼文を自由文で入力する | 必須 |
| F2 | 自分の状況入力 | 手動入力（残り時間・優先度・制約）または Google Calendar から取得を選択し、状況を反映する | 必須 |
| F3 | 返信案生成 | 依頼文＋自分の状況を送り、AIで返信案を1件生成する | 必須 |
| F4 | 返信案表示 | 生成された返信案1件を表示する | 必須 |
| F5 | 返信案のコピー | 表示された返信案をユーザーがコピーして利用できる | 必須 |

---

## 2. 画面・UI概要

### 2.1 画面構成（単一画面想定）

- **入力エリア**
  - 依頼文：テキストエリア（自由文）
  - 自分の状況の入力元：手動入力 / Google Calendar から取得（ラジオ等で選択）
  - 手動選択時：残り時間・優先度・制約を入力
  - Google Calendar 選択時：対象日（YYYY-MM-DD、省略時は今日）を指定
  - 生成実行ボタン
- **出力エリア**
  - 返信案1件をカードまたはブロックで表示
  - 「コピー」ボタンでコピー可能な表示

### 2.2 入力仕様（自分の状況）

- **入力元**: 手動入力 または Google Calendar から取得。いずれかを選択する。
- **手動入力時**

| 項目 | 形式 | 必須 | 備考 |
|------|------|------|------|
| 残り時間 | 数値 | 任意 | 単位は時間。小数可（例：1.5） |
| 優先度 | 3段階選択 | 任意 | 値のラベルは設計時に確定（例：高・中・低） |
| 制約 | 自由文 | 任意 | NG・落とし所・既存優先などを記述 |

- **Google Calendar 取得時**: 対象日（YYYY-MM-DD、省略時は今日）を指定。BE が MCP 経由で予定を取得し、残り時間・制約を導出する。

## 3. データフロー（概要）

```
[ユーザー]
  → 依頼文を入力
  → 自分の状況の入力元を選択（手動 / Google Calendar）
  → 手動の場合は残り時間・優先度・制約を入力、カレンダーの場合は対象日を指定
  → 生成実行
[FE]
  → POST /api/v1/reply-drafts に依頼文＋situation_source＋（手動時は remaining_hours/priority/constraints、カレンダー時は calendar_date）を送信
[BE]
  → 入力検証
  → situation_source=calendar のときはカレンダー Port（MCP）で予定取得 → 残り時間・制約を導出
  → MySituation を組み立て → Usecase 呼び出し
  → 返信案生成エージェントで初稿を生成
  → 返信案チェックエージェントでチェック（3項目を10点満点で評価、全て8以上でOK。NG なら must_fix / nice_to_have を渡して作り直し）
  → NG の場合は返信案作り直しエージェントで修正（最大 N 回まで、またはスコア合計が改善しない場合は終了）
  → 最終的な返信案 1 件を draft としてレスポンス返却
[FE]
  → 返信案1件（draft）を表示
  → ユーザーがコピー
```

- 複数エージェントの詳細（役割・フロー・終了条件）は [architecture.md](architecture.md) の「3.5 複数エージェントの組み合わせ」を参照。

---

## 4. 出力仕様（返信案）

- 返信案は**テキスト**で、以下を満たすことをAIに指示する（プロンプトで定義）：
  - 角の立たない断り
  - 代替案（スコープ縮小／期限延長／分割／他者紹介／優先順位調整のいずれかまたは複数）
  - 相手に投げる確認質問
  - 次の一手（2ターン目の返信に使える一文・提案）
- 返信案の数：1案。

---

## 5. エラー・例外

| 状況 | 方針 |
|------|------|
| 依頼文が空 | バリデーションでエラーまたは警告。BEで拒否してもよい。 |
| AI API 障害・タイムアウト | エラーメッセージを表示し、再実行を促す。 |
| ネットワークエラー | 同様にエラー表示と再実行の案内。 |
| カレンダー取得失敗（situation_source=calendar 時） | BE が 503 を返す場合あり。エラー表示と再実行または手動入力への切替を案内。 |

---

## 6. 非機能（本ドキュメントで扱う範囲）

- **可用性**: デモ用途のため、 SLA は特になし。
- **性能**: 生成は複数エージェント（生成→チェック→作り直し）のため、数秒〜数十秒程度を想定。タイムアウトは API 契約で定義する。
