## コンテキスト

「上司案件・落とし所AIエージェント」の開発を進めるにあたり、スコープ・利用者・入出力仕様・技術方針について不明点があったため、質問リストを提示し回答を得た。本 ADR はその回答を**アーキテクチャ／要件の決定事項**として記録する。

---

## 決定事項

### 1. スコープ・成果物

**質問**: 「AIエージェントを作成する」の範囲はどれか。

**決定**: **A) アプリ全体（React UI ＋ FastAPI バックエンド ＋ AI 連携）を一通り実装する**

- フロントエンド（React）・バックエンド（FastAPI）・AI 連携を一体的に実装する。
- API のみ先行する形はとらない。

> 2025-02-07 付でフロントエンドを React/Next.js（App Router）に変更。詳細は [ADR-0003](adr-0003-フロントエンドReactからNext.js-App-Routerへ.md) を参照。

---

### 2. 利用者・認証

**質問**: 利用想定はどれか（個人／複数ユーザー／認証の有無）。

**決定**: **デモアプリとして認証なしで作成する**

- ログイン・認証は実装しない。
- デモ用途を前提とする。

---

### 3. 入力「自分の状況」の形式

**質問**: 時間／優先度／制約をどう入力するか。

**決定**:

- **時間**: 数値入力とする。
- **優先度**: 3 段階で選択する。
- **制約**: 自由文とする。

（フォーム＋補足の自由文に近いが、時間は数値・優先度は選択・制約は自由文と明示）

---

### 4. 出力の扱い

**質問**: 返信案 A/B/C をどう提供するか。

**決定**: **複数案を一度に表示し、ユーザーが選んでコピー等する**

- 返信案を一覧で同時表示する。
- 1 案ずつの切り替え表示や、アプリ内での編集 UI は必須としない（選んでコピーする運用でよい）。

---

### 5. AI モデル名

**質問**: 利用する OpenAI モデルの正式名。

**決定**: **gpt-5-mini**

- 実装時点で API 上利用可能なモデル名に合わせて指定すること。
- （注: リリース時期によっては gpt-4o-mini 等の別名の可能性あり。実装時に API 仕様を確認すること。）

---

### 6. PydanticAI の扱い

**質問**: バックエンドで PydanticAI を必ず使うか。

**決定**: **はい — FastAPI + PydanticAI でエージェントを実装する**

- バックエンドの AI 呼び出しは PydanticAI を採用する。
- OpenAI SDK 直叩きや LangChain 等は採用しない方針とする。

---

### 7. 永続ドキュメント（./docs）の初期状態

**質問**: ./docs や product-requirements.md 等を今回のタスクで新規作成してよいか。

**決定**: **はい — 今回のエージェント仕様に合わせて docs を一から作成する**

- `./docs` および AGENTS.md で定める永続ドキュメント（product-requirements.md、functional-design.md、architecture.md 等）を、本プロダクト用に新規作成してよい。
- 既存テンプレの指定はない。

---

## 結果・影響

- **スコープ**: FE + BE + AI のフルスタック実装となり、タスク量は相応に増える。
- **認証**: 未実装のため、デモ・検証用途に限定される。
- **UI**: 時間（数値）・優先度（3 段階選択）・制約（自由文）の入力と、返信案の一覧表示・コピーが必須仕様となる。
- **技術**: バックエンドは FastAPI + PydanticAI、モデルは gpt-5-mini（または API 仕様に合わせた同等モデル）とする。
- **ドキュメント**: ./docs を本プロダクト用に初期作成し、以降の仕様・設計はここに集約する。
