# ADR-0002: 複数 AI エージェント（生成→チェック→作り直し）フロー採用

## メタデータ

| 項目 | 値 |
|------|-----|
| ステータス | Accepted |
| 日付 | 2025-02-07 |
| 決定者 | プロダクトオーナー |

---

## コンテキスト

返信案の品質を高めるため、単一の AI エージェントで一括生成するのではなく、**複数の AI エージェントを組み合わせたフロー**を採用する。生成した返信案をチェックし、必要に応じて作り直すことで、角の立たなさ・代替案の有無・制約違反の有無などを担保する。

---

## 決定事項

### 1. 複数エージェントの役割

**決定**: **3 種類のエージェント**を組み合わせる。

| 役割 | エージェント名 | 入力 | 出力 |
|------|----------------|------|------|
| **生成** | 返信案生成エージェント | 依頼文＋自分の状況 | 返信案リスト（初稿） |
| **チェック** | 返信案チェックエージェント | 返信案リスト＋依頼文・自分の状況 | チェック結果（OK/NG、指摘・改善点） |
| **作り直し** | 返信案作り直しエージェント | 返信案リスト＋チェック指摘＋依頼文・自分の状況 | 返信案リスト（修正版） |

- 各エージェントは PydanticAI で実装する。
- Application 層からは Port（抽象）経由で呼び出し、Infrastructure が各 Adapter として実装する。

---

### 2. フロー（生成→チェック→作り直し）

**決定**: 以下の順で実行し、必要なら繰り返す。

1. **生成**: 依頼文＋自分の状況 → 返信案生成エージェント → 返信案リスト（初稿）
2. **チェック**: 返信案リスト＋依頼文・状況 → 返信案チェックエージェント → チェック結果（OK または NG＋指摘）
3. **作り直し（条件付き）**: チェックが NG の場合、指摘を渡して返信案作り直しエージェントを実行 → 返信案リスト（修正版）
4. **終了条件**: チェックが OK になるまで、または **最大 N 回**の作り直しに達するまで繰り返す。最終的な返信案リストを API レスポンスとして返す。

- 最大作り直し回数 N は実装時に定義する（例: 1〜2 回）。無限ループを避ける。
- チェックの基準（何を OK/NG とするか）はプロンプトで定義する（例: 角の立たなさ・代替案の有無・制約違反の有無）。

---

### 3. API 契約への影響

**決定**: **FE から見た API 契約は変更しない**

- エンドポイントは従来どおり 1 回の POST（例: `POST /api/v1/reply-drafts`）。
- リクエスト・レスポンスの型は変更しない。複数エージェントの組み合わせは BE 内の実装詳細とする。
- FE は「依頼文＋自分の状況」を送り、「返信案リスト」を受け取るだけとする。

---

### 4. 非機能（性能）

**決定**: 複数エージェント実行を前提に、生成時間の想定を「数秒〜数十秒程度」とする。

- タイムアウトは API 契約で定義する。
- 作り直し回数 N が大きいほど遅延が増えるため、N は 1〜2 回程度に抑える方針とする。

---

## 結果・影響

- **アーキテクチャ**: architecture.md に「3.5 複数エージェントの組み合わせ」を追加済み。Infrastructure は 3 つの PydanticAI エージェント（生成・チェック・作り直し）を呼ぶ Adapter を実装する。
- **機能設計**: functional-design.md のデータフロー（3）を「生成→チェック→作り直し（最大 N 回）」に更新済み。
- **用語**: glossary.md に「返信案生成エージェント」「返信案チェックエージェント」「返信案作り直しエージェント」「チェック結果」を追加済み。
- **実装タスク**: implementation-tasklist.md の B4（ユースケース＋Port）は「生成→チェック→作り直しのオーケストレーション」、B5 は「3 エージェントの実装」として反映済み。
- **API**: FE 向けの契約は変更なし。BE 内のユースケースが複数 Port（または 1 Port で 3 エージェントを内包）を組み合わせて返信案を返す。
